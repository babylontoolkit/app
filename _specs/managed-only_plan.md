# Managed Only: every turn and the enhancer on Anthropic Managed Agents

**Goal.** With `AGENT_ENGINE=managed` (the default), NO request reaches the legacy engine (`proxy.ts` `streamText` loop) or the provider chain (`LLM_PROVIDER_CHAIN` / KIE / Comet). Today three paths still do: **Plan mode turns**, **turns that carry MCP tools**, and the **prompt enhancer (✨)**. Each moves onto Managed Agents.

**Why (owner, 2026-10-03).** *"I dont want to use the old system at all... IT IS UNRELIABLE, HENCE PAYING FULL PRICE AND USING THE NATIVE ANTHROPIC MANAGED AGENT... MAKE the Managed Agent the only safe and reliable LLM_PROVIDER."*

> **Superseded in part the same day by `_specs/anthropic-only_plan.md`:** the `AGENT_ENGINE=legacy` kill switch below is gone, Anthropic is the only LLM provider, and Comet was removed.

**Scope.** The three paths above, the routing that sent them to legacy, the cache warmer (it warms a legacy prefix nobody sends on a managed deploy), and the docs. **Kept (hide-don't-delete):** the legacy engine code and `AGENT_ENGINE=legacy` as the kill switch, byte for byte. **Not in scope (stated so nobody assumes otherwise):** the Unity Bridge tools and the web-search tool are offered only by the legacy loop; a managed turn simply does not offer them. Both are capability gaps, not routing paths, and are separate work.

---

## Decisions

- **D1 — Plan mode is enforced in the managed DISPATCHER, not by changing the agent's tools.** The tool list stays constant (one provisioned agent per rung, hash-skipped; flipping tools per turn needs an idle session and churns the cache). On a Plan turn the dispatcher refuses every call that could change the project or spend: `project_write` / `project_edit` outside `_specs/` (the SAME `isPlanArtifactPath` rule and `PLAN_ONLY_REFUSAL` sentence the legacy `planOnly` tools use), `project_run`, `check_game`, `evaluate_in_game`, `generate_*` (refused before any debit) and `mcp_call`. Reads (`project_read/list/grep`, `mcp_list_tools`), `update_todos` and the read-only preview tools (`get_game_errors`, `get_game_console`, `capture_game_screenshot`) stay. The refusal is a server-side wall; the message note (D2) is guidance only.
- **D2 — The Plan note rides in the turn's `user.message`, prefixed.** Not a `system.message` (that persists for every later turn and is model-gated — Sonnet 5 rejects it). The note is the managed wording of `discuss-note.ts` (names `project_write`, says "this turn only"). A Build turn that follows a Plan turn (the previous assistant message carries `PLAN_MODE`) is prefixed with a one-line "Plan mode has ended", so the session's memory of the Plan note cannot linger.
- **D3 — A managed Plan turn looks like a legacy one to the client.** `discussMode: true` on the generation, so the route writes `PLAN_MODE` then `NO_REPLAY` (same order, same reason); the server-written transcript carries both marks so "Build this plan" / "Build & Apply" survive a reload; `statusKind` is the plan kind; a Plan turn never runs build phases and never records a finished build (`recordManagedBuildPhases`), and is never treated as a first build for its outcome.
- **D4 — MCP is TWO constant custom tools, `mcp_list_tools` and `mcp_call {server, tool, arguments}`.** Per-MCP-tool custom tools would change the session's tool list per project (an idle-session update every turn and a cold cache). The list is answered by the server from the request's `mcpTools` (description + schema capped at the legacy 1,500 chars per tool). `mcp_call` resolves by `(server, tool)` EXACTLY — never by name alone (CLAUDE.md §4.14) — emits the existing `mcp-tool-call` data part, and awaits the existing `/api/agent/tool-result` relay. The browser half is unchanged.
- **D5 — An MCP relay timeout is answered to the agent, unlike a workspace timeout.** Workspace/preview timeouts detach (the browser is gone, D6 of the engine plan). An MCP timeout is usually a slow third-party server, so the legacy answer is kept: an error result ("could not run: …"). A detached request still answers nothing. `mcp_call` is serialised with the other mutating tools (an MCP server can write files).
- **D6 — Each MCP turn's message says the tools exist in one line** (N tools, server names, "call `mcp_list_tools`"), never the whole list: the session keeps every message forever, so a per-turn list would grow the history on every turn.
- **D7 — Sessions get the CURRENT tool list.** New sessions are created with `tools: [builtin, ...MANAGED_CUSTOM_TOOLS]` in `agent_with_overrides`, so a deploy that added `mcp_*` works before an admin re-synchronizes. An existing session whose agent lacks `mcp_call` is updated (`sessions.update`, session idle) on the first turn that carries MCP tools; a failure is logged and the turn runs without them.
- **D8 — The enhancer is a one-shot Managed Agents session on the Standard rung's agent, with overrides** — `system` = the enhancer prompt, `tools: []`, `skills: []` (skills need the `read` tool, so both are cleared), `model` = `getEnhancerModel(context, 'Anthropic')` (`ANTHROPIC_ENHANCE_PROMPT_MODEL` → `ENHANCE_PROMPT_MODEL` → `LLM_MODEL`). No new agent to provision or store. No reference files are mounted.
- **D9 — The enhancer bills the session exactly as a managed turn does**: `sessionCost` over the session's threads → `decideManagedCharge` against an EMPTY cursor (a one-shot session) → `settleGeneration` with `flatCredits` + `rawCostOverrideUsd`, `statusKind: 'enhance'`. The no-unbilled-usage rules hold: credit gate before the session; a `running` row (engine `enhancer`, `managedSessionId` set) before the first message; settlement under `keepAlive`; failed (error or no text) → refunded; the session archived after settlement. BYOK does not apply (managed runs on the platform key, engine plan D8).
- **D10 — The billing sweep settles a dead enhancement from its session.** A stale `running` `enhancer` row with a `managedSessionId` is priced from the session (D9) and marked `interrupted`, never refunded; without one it keeps today's checkpoint settlement. A session still running is interrupted and left for the next sweep.
- **D11 — Routing:** `selectEngineForTurn` returns the deploy's engine for every turn. The cache warmer skips its cycle on a managed deploy (`runWarmCycle` → skipped "managed engine").

## Results (2026-10-03)

- **Gates:** `pnpm typecheck` clean; `pnpm lint` 0 errors; `pnpm test` 9,523 passed (454 files). New specs: `dispatch-plan-mcp.spec.ts` (15), `enhance.spec.ts` (5), Plan/MCP cases in `engine-turn.spec.ts` (4), `message.spec.ts` (4), `tools.spec.ts` (1), the managed enhancement in `sweep.spec.ts` (4), the warmer skip in `cache-warmer.spec.ts` (2). Mutation-checked: removing the Plan refusal, resolving MCP by name alone, routing a Plan write through the unwalled workspace, the session-tool update condition, the transcript marks, the enhancer refund, the running row's session id, the no-text failure rule and the sweep's enhancement branch each fail a test.
- **Live against Anthropic (local dev server, real key):**
  - Enhancer: HTTP 200, first text 1.9 s, done 15.2 s; row `completed`, `engine: enhancer`, `managedSessionId` set; 4 in / 1,255 cache-write / 1,433 out on Sonnet 5.5 → 6 credits (warm basis ≈ $0.015 × 4; true cost $0.02 ≤ 6 credits' worth).
  - Plan turn: `plan-mode` then `no-replay` before any text; the agent's `project_write` to `src/` was refused by the wall and it quoted `PLAN_ONLY_REFUSAL`; 7.6 s, 4 credits; transcript annotations `plan-mode, no-replay, usage, agentMeta, agentWorkspace, credits`; row `statusKind: plan`, `engine: managed`.
  - MCP turn: a NEW session listed the request's MCP tool through `mcp_list_tools` (server `docs`, tool `search_docs`); 6.5 s, 3 credits.
- **Not live-driven:** an `mcp_call` relayed to a real MCP server in a browser sandbox (needs the UI + a project `.mcp.json`; covered by the relay tests over the real in-process relay), a `_specs/` write through the browser executor on a managed Plan turn (same executor path as every managed write), and the sweep's dead-enhancement recovery against a real session.
- **Found, not changed (out of scope):** the enhancer's prompt (unchanged from legacy) is generic — on the live run it suggested Three.js for a "kart racing game", which contradicts the Babylon-only rule; and the platform's credit formula `ceil(cost / unit × margin)` has no float epsilon, so a cost that lands exactly on a credit boundary can round up by one (e.g. $0.07 → 29, not 28).
