**Deviations from the spec, decided here** (each also recorded in `## Decisions`):
1. **The tool-round budget grows when bridge tools are present** (D18). Spec B5 said it was unchanged, but
   research found `maxToolRounds` is 7 with no headroom; one Unity export → capture → verify loop needs more.
2. **Consent is asked BEFORE any debit** (D16). A denial writes no ledger rows at all, instead of the
   spec's debit + refund. The net cost is the same, zero, with fewer rows.
3. **`BuildProject`'s `SaveOpenScenes()` is kept** (D30). Unity's own command doc says the exporter reads
   scenes from disk. The protection moves to the CLI (`--scene` refuses a dirty scene) and to the helper
   (refuses to export or close over unsaved changes).
4. **`MakeSafeWebRequest`** (D32). It loses its hardcoded Basic-auth header. The form `secret` value is also
   the licence-file decryption key (`GetKeyPhrase()`), so it is left in place and flagged, not changed.

**Gaps deliberately not closed:**
- The exact JSON shape `unity command` returns for `list_open_scenes` is not documented. T23 parses it
  defensively (D39).
- Whether Lightsail's proxy tolerates a 25 s held request is unverified. D6 keeps the hold under common

- The prompt re-sync fetches `babylontoolkit/agent` from GitHub, not the local clone, and one missing document

## Decisions

- **D1 — The helper is the Desktop Agent's `bridge` command, not its own package (owner, 2026-09-27).** It
  lives in `/Users/mackey/Documents/Repos/Babylon/Repositories/UniversalSkills` (npm `@babylonjs-toolkit/agent`,
  CLI `bt-agent`, GitHub `babylontoolkit/skills`) as `lib/bridge/`, reached as `bt-agent bridge`. One install
  gives skills, persona and the bridge, and the package already has cross-platform paths (`lib/paths.js`),
  self-update (`bt-agent update`) and `doctor`. Rejected: a separate `@babylonjs-toolkit/bridge` package (a
  second install and a second update path). **Everywhere in this plan, "the helper" means this `bt-agent bridge`
  service running on the user's machine.** Binds: T23–T26.
- **D2 — The bridge follows the Desktop Agent's conventions: plain CommonJS JavaScript (`'use strict'`,
  `require`), no build step, zero runtime dependencies, Node ≥ 18 (global `fetch`/`AbortController`), tests as
  `tests/bridge-*.test.js` run by the package's existing `node --test tests/*.test.js`.** Rejected: TypeScript
  + a bundler inside a package that has no build (a toolchain for one module). Binds: T23–T25.
- **D3 — Two copies of the policy, one authority per side.** The server's `app/lib/bridge/` (`protocol.ts`,
  `tiers.ts`, `pricing.ts`, `validate.ts`) decides pricing, the Consent prompt and early refusals. The Desktop
  Agent's `lib/bridge/policy.js` is a CommonJS port of `tiers.ts` + `validate.ts` + `capText` + the protocol
  constants, and it is **authoritative on the user's machine**: it enforces its own table whatever the server
  sent. A disagreement can therefore only produce a refused (refunded) call, never a looser rule. Both copies
  are pinned by the SAME named cases (T14's `tiers.spec.ts` / `validate.spec.ts` cases, copied verbatim as
  data into `tests/bridge-policy.test.js` in T24). `BRIDGE_PROTOCOL_VERSION` (1) rides in every poll's `hello`;
  a mismatch is a 426 telling the user to run `bt-agent update`. Rejected: one shared module (the agent has no
  build step to bundle TypeScript, and a policy fetched from the server would let a compromised server loosen
  the user's own wall). Binds: T14, T17, T24.
- **D4 — Transport is HTTPS long-poll.** Workerd forbids writing to a socket from another request.
  Rejected: WebSocket, and a browser → localhost companion (the §4.17 failure). Binds: T17, T23.
- **D5 — One server instance holds all bridge state in memory** (owner, 2026-09-27). This covers presence,
  queues, parked polls and job handles. Durable facts go to `bridge_jobs`. Rejected: Redis or Durable
  Objects. Binds: T17, T26.
- **D6 — Timing constants:**

  | Constant | Value |
  |---|---|
  | `BRIDGE_POLL_HOLD_MS` | 25_000 |
  | `BRIDGE_PRESENCE_MS` | 45_000 |
  | `BRIDGE_PICKUP_TIMEOUT_MS` | 30_000 |
  | `BRIDGE_SYNC_WAIT_MS` | 60_000 |
  | `BRIDGE_JOB_WAIT_MAX_S` | 90 |

  | `BRIDGE_JOB_RETENTION_MS` | 600_000 |
  | `BRIDGE_LAST_SEEN_WRITE_MS` | 60_000 |

  Binds: T14, T17, T18, T23.
- **D7 — Device-code pairing.**
  - The helper `start`s a pairing and gets `{pairingId, secret, code}`.
  - The user approves the 8-character code (alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`, shown as
    `XXXX-XXXX`) in the builder's Connect dialog, opened from the cube icon in an open project's chat box.
    There is no approve URL: the icon only exists inside a project, so a link to the landing page could never
    open the dialog.
  - The helper `redeem`s it with `pairingId + secret` and receives a device token **once**.
  - The server stores only a SHA-256 hex hash of the token and of the secret. Codes expire in 10 minutes.
  - Limits: 5 active devices per user; approve is rate-limited to 10 per 10 minutes per user; start is
    rate-limited to 20 per hour per caller fingerprint.

  Rejected: a pasted session cookie, or a shared platform key. Binds: T16, T21, T23.
- **D8 — Token format** is `btkb_` + 32 random bytes base64url. It is presented as
  `Authorization: Bearer <token>` and never in a query string. Binds: T16, T23.
- **D9 — New tables** `bridge_devices`, `bridge_pairings` and `bridge_jobs`, plus a new column
  `projects.bridge_link jsonb`, all in migration `0025_unity_bridge.sql`. RLS is enabled with **no policy**
  (the `git_tokens` precedent). The migration also adds `'bridge'` to `credit_ledger_reason_check`.
  Binds: T15.
- **D10 — Ledger reason `bridge`, never allowed to go negative.** It is debited BEFORE dispatch. Absent from
  `mayGoNegative`. Binds: T15, T18.
- **D11 — Prices are config.**

  | Variable | Default | Applies to |
  |---|---|---|
  | `BRIDGE_COMMAND_CREDITS` | 1 | commands, CLI operations, editor open/close, dev-server start |
  | `BRIDGE_SCRIPT_CREDITS` | 2 | C# and Blender scripts |
  | `BRIDGE_JOB_CREDITS` | 4 | the long operations in `LONG_COMMANDS` / `LONG_CLI` |

  - Free: listing commands, job status/wait/cancel, dev-server status, editor status, and scene import.
  - `0` disables a price.
  - A negative or non-numeric value falls back to the default (the `projectCreateCredits` pattern,
    `billing/rates.ts:852–864`).

  Binds: T14, T18.
- **D12 — The job id is also the generations anchor id,** `brg_<base36 time>_<6 base36 random>`. Binds: T16, T18.
- **D13 — A charge stands once the helper reports `started`; everything else is refunded exactly once, by
  ONE function.** A job that never reported `started` is refunded. The causes are: pickup timeout, cancelled
  while queued, device revoked or logged out, generation ended while still queued, or the helper refused it.
  - **One refund writer:** `settleNotStarted(jobId, status, reason, context)` in `service.ts`. Every
    not-started path calls it — the pickup timeout, `cancelJob`, logout, generation end, and a helper
    `refused` event. Nothing else calls `refundBridgeJob`.
  - **Latch 1 (row):** it loads the row and returns if the status is already terminal (`succeeded`, `failed`,
    `refused`, `cancelled`) or `started === true`. Otherwise it writes the new terminal status FIRST, then
    refunds.
  - **Latch 2 (database):** the refund's ledger `note` is exactly `bridge:<jobId>`, and migration 0025 adds
    the partial unique index `credit_ledger_bridge_refund_idx on credit_ledger (user_id, note) where reason =
    'refund' and note like 'bridge:%'` (the `project_create` precedent, migration 0015). A unique-violation on
    append is treated as "already refunded" and logged, never alerted.
  - **The refund amount is what was actually debited**, and the row's `credits` stores that amount (0 in
    unmetered mode). A zero-credit row writes no refund.
  - **A late `started`** (after the pickup timeout already cancelled and refunded) is ignored. The relay marks
    the entry `dropped`, `deliverBridgeEvent` returns `false` for it, and `onEvent` never writes a row whose
    status is terminal. The helper receives the cancel on its next poll and kills the child. If it had
    already begun, that run is uncharged — the accepted, user-favourable residual.

  Binds: T15, T17, T18.
- **D14 — Tier model** (`allowed | scripts | consent | refused`) is decided by `classifyOperation` in

- **D48 — Grant format.**

    ASCII bytes of the first segment.
  - The payload is `{ v: 1, iss: 'babylon-toolkit-app-builder', sub: <userId>, dev: <deviceId>, prj: <productGUID, 32 lowercase hex>, iat: <unix s>, exp: <unix s> }`.
  - The lifetime comes from `BRIDGE_GRANT_TTL_HOURS` (default 12, clamped to 1–24). The DLL refuses any

  Binds: T27, T28, T24.
- **D49 — Key material.**

    `BRIDGE_GRANT_PRIVATE_KEY` (a secret: never `VITE_`-prefixed, never logged, never in a response).
  - The public key is compiled into the DLL as two base64 constants (modulus, exponent), because
    `RSA.ImportParameters` works on every Unity/Mono runtime where the newer SPKI importers may not.
  - Both are produced by `scripts/bridge-grant-key.mjs generate`.
  - The executor generates the key pair once, writes the private key to `.env.local` (gitignored, verified:
    `.gitignore:35`) and pastes the public constants into C#. The owner copies the private key to SSM before
    deploying; rotating it means regenerating and rebuilding the DLL.
  - Missing private key → the grant route answers 503 `NotConfiguredError`, and the bridge carries on without
    automation.

  Binds: T27, T28, T26.
- **D50 — Who gets a grant.** The grant route runs `decideSubscriptionAccess` (§4.18a: an active Stripe
  subscription OR credits > 0) for the device's user through a new `checkAccessForUser(userId, context)` in
  `licensing/subscriber-status.ts`. An inactive account → `BridgeRefusedError(403)`. The requested
  `productGuid` must also appear in that device's advertised `hello.unityProjects` (else 403). The route is
  rate-limited to 60 per hour per device. Binds: T27.
- **D51 — The Desktop Agent delivers the grant; the model never sees it.**
  - Discovery reads `productGUID:` from `ProjectSettings/ProjectSettings.asset` into
    `BridgeUnityProject.productGuid`.
  - Before every `bt_*` `unity.command`, the helper ensures it holds a grant for that project with more than
    2 h left (fetching `POST /api/bridge/grant` otherwise). It then runs

  - Grants are kept in helper memory only and never written to disk, logged, or put in job results.

  Binds: T24, T27.
- **D52 — Local scenes never wait on the bridge.** Spec A7 says import "works **without** the bridge". That

  - the dev-server origin, **Check**, the helper's scene list, the free-text URL and **Import** are ONE

    dialog (first section) and the Status panel. The Unity icon opens one of the two in every state

  - without an online helper there is no scene list (`scenes` comes only from `hello.devServer`); the

**`app/lib/bridge/tiers.ts`**
```ts
import type { BridgeOperation } from './protocol';
export type BridgeTier = 'allowed' | 'scripts' | 'consent' | 'refused';
export interface TierDecision { tier: BridgeTier; reason?: string }

export const SCRIPT_COMMANDS = new Set(['run_script', 'eval', 'eval_file']);
export const CONSENT_COMMANDS = new Set([
  'set_import_settings', 'delete_gameobject', 'delete_asset', 'move_asset', 'rename_asset',
  'package_remove', 'package_resolve', 'set_player_settings', 'set_quality_settings',
  'set_physics_settings', 'set_tags_layers', 'set_lighting_settings', 'set_navmesh_settings',
  'set_build_settings', 'build_player',
]);
export const CONSENT_COMMAND_PATTERN = /^(delete|remove|move|rename|clear|reset|uninstall)_/;
export const ALLOWED_COMMAND_PATTERN =
  /^(get|find|list|search|create|add|set|instantiate|open|save|import|bake|capture|screenshot|console|editor|package_add|package_status|wait_for|recompile|run_tests|bt_|select|apply|assign|attach|duplicate|load|play|stop|pause|refresh|describe|inspect)/;

export const REFUSED_CLI: Record<string, string> = {
  command: 'use the unity_command tool',
  cmd: 'use the unity_command tool',
  open: 'use the unity_editor tool',
  close: 'use the unity_editor tool',
  run: 'not available through the Unity Bridge',
  shell: 'not available through the Unity Bridge',
  mcp: 'not available through the Unity Bridge',
  skill: 'not available through the Unity Bridge',
  job: 'use the bridge_job tool',
};
/** first arg → allowed second args ('*' = any). */
export const ALLOWED_CLI: Record<string, string[] | '*'> = {
  status: '*', logs: '*', recompile: '*', test: '*', templates: '*', releases: '*', doctor: '*',
  docs: '*', list: '*', editors: ['list', 'path', 'running'], projects: ['info', 'verify'],
  vcs: ['diff', 'blame', 'status'], assets: ['export'], pipeline: ['list', 'list-versions', 'status'],
};
export const CONSENT_CLI = new Set(['license', 'auth', 'install', 'uninstall', 'install-modules',
  'self-update', 'build', 'projects', 'vcs', 'assets', 'pipeline']);   // reached only when not ALLOWED above

export function classifyOperation(op: BridgeOperation): TierDecision;
```
The classification rules, in order:

**`unity.command`**
1. A name in `SCRIPT_COMMANDS` → scripts.
2. A name in `CONSENT_COMMANDS` or matching `CONSENT_COMMAND_PATTERN` → consent.
3. `batch` → the highest tier of `params.commands[].name`, ranked `allowed < scripts < consent`. A missing
   or non-array `commands`, or an entry without a string `name`, → consent.
4. A name matching `ALLOWED_COMMAND_PATTERN` → allowed.
5. Anything else → consent, with reason `unrecognised command — asking first`.

**`unity.cli`**
1. An empty `args` → refused.
2. `args[0]` in `REFUSED_CLI` → refused, with that reason.
3. The `ALLOWED_CLI` entry for `args[0]` is `'*'`, or it includes `args[1]` → allowed.
4. `args[0]` in `CONSENT_CLI` → consent.
5. Anything else → consent.

**Everything else**
- `unity.script` and `blender.script` → scripts.
- `unity.list`, `unity.capture`, `unity.editor` (every action), `devserver.start` and `devserver.status` →
  allowed.

Semantics:
- **Queue order:** first in, first out per device.
- **`pollBridgeJobs`**
  - It first calls `touchDevice(deviceId, undefined)`.
  - If there are queued jobs or pending cancels, it returns them immediately. Queued jobs are marked
    `dispatched`.
  - Otherwise it parks one waiter per device, replacing and resolving any previous waiter with
    `{jobs:[],cancels:[]}`, until `holdMs` elapses, a job arrives, or `signal` aborts.
- **`deliverBridgeEvent`**
  - It returns `false` and does nothing for an entry whose state is `dropped` (a late `started` after a
    cancel — D13). Otherwise it updates the job's state and calls `onEvent`.
  - `started` marks the job started.
  - `final` and `refused` settle it and schedule removal after `BRIDGE_JOB_RETENTION_MS`.
- **`cancelBridgeJob`**
  - A queued job → state `dropped`, removed from the queue; returns `'dropped'`.
  - A dispatched job (not started) → state `dropped` AND a cancel appended to the device's pending cancels;
    returns `'dropped'` (it never started, so it is refundable).
  - A started job → only the cancel is appended (state unchanged, still charged); returns `'signalled'`.

1. `fetch(origin + '/', { mode: 'cors', cache: 'no-store' })` resolves → `running`, regardless of status.
2. It throws → try `fetch(origin + '/', { mode: 'no-cors', cache: 'no-store' })`. If that resolves →

3. Both threw → `navigator.permissions.query({ name: 'loopback-network' as PermissionName })`, then the same

`planSceneImport`:

- A `.gltf` → the scene file itself, plus every `buffers[].uri` and `images[].uri`. Each URI is:
  - skipped with `embedded data URI` when it starts with `data:`;
  - skipped with `absolute URL — not copied` when it contains `://`;
  - skipped with `outside the scene folder` when, after `decodeURIComponent`, it starts with `/` or has a

- A disabled bridge (`!isBridgeEnabled`) answers every route in this table with
  `json({ error: true, message: 'The Unity Bridge is not enabled on this server.' }, { status: 404 })`, except
  the project `GET`, which returns `{enabled:false, …}` with 200 so the icon can hide itself.
- On `POST /api/bridge/poll`, the route sets `touchDevice(device.id, body.hello)`. When `body.hello` is
  present and ≥ `BRIDGE_LAST_SEEN_WRITE_MS` has passed since the last write (or the stored capabilities
  differ), it persists `capabilities` and `lastSeenAt`. It then returns
  `await pollBridgeJobs(device.id, BRIDGE_POLL_HOLD_MS, request.signal)`.
- `POST /api/bridge/result` with `{action:'logout'}` does two things:
  - stores `revokedAt`;
  - calls `dropDevice(device.id)`, which returns the ids of that device's queued AND

### Control flow

**`runBridgeOperation(op, label, ctx)`**
1. `validateOperation(op)`, and on a sentence return `` `The Unity Bridge refused this: ${sentence}` ``.
2. `const { tier, reason } = classifyOperation(op)`.
   - `refused` → return `` `The Unity Bridge does not run this: ${reason}` ``.
3. `tier === 'scripts' && !ctx.link.allowScripts` → return
   `Scripts are switched off for this Unity link. Ask the user to turn on "Allow scripts" in the Unity Bridge panel (the cube icon), then try again.`
4. `tier === 'consent'`:
   1. `ctx.emit({type:'bridge-consent', toolCallId: ctx.toolCallId, operation: label, tier:'consent', target: ctx.link.unityProjectName})`.
   2. `const answer = await awaitClientToolResult({ generationId: ctx.generationId, toolCallId: 'consent:' + ctx.toolCallId, userId: ctx.userId, abortSignal: ctx.abortSignal, timeoutMs: BRIDGE_CONSENT_TIMEOUT_MS })`.
   3. Continue only if `answer.result && (answer.result as {approved?: unknown}).approved === true`.
   4. Otherwise return `` `The user did not allow this operation (${label}). Nothing ran and nothing was charged.` ``.
5. `const credits = creditsFor(op, bridgePrices(ctx.context))` and `const jobId = mintId('brg')`.
6. `let debited = 0; if (credits > 0) ({ debited } = await anchorAndDebit({ jobId, userId, projectId, credits, label, context }))`.
   - A `BridgeRefusedError` (402) → return `` `Not enough credits for this Unity operation (${credits} credits). The user can add credits and try again.` ``.
7. `putJob({ id: jobId, userId, projectId, deviceId, operation: label, tier, status:'queued', credits: debited, started:false, createdAt })`,
   then `emit({type:'bridge-job', jobId, status:'queued', label, credits: debited})`.
8. `enqueueBridgeJob({ deviceId, userId, generationId, dispatch: { jobId, op, unityProjectKey: link.unityProjectKey, allowScripts: link.allowScripts, consentGranted: tier === 'consent' }, onEvent })`.
   `onEvent` does the following, never throws, and never writes over a terminal row:
   - `started` → `putJob({...row, status:'running', started:true})`, then emit `running`.
   - `progress` → emit `running` with `line`.
   - `final` → `putJob` with status `succeeded` / `failed` (`result.ok`), `resultText: capText(result.text)`,
     `finishedAt`, then emit.
   - `refused` → `settleNotStarted(jobId, 'refused', reason, context)` (writes `error: reason`), then emit.
9. `const started = await handle.waitStarted(BRIDGE_PICKUP_TIMEOUT_MS, ctx.abortSignal)`. If it is `false`:
   1. `cancelBridgeJob(jobId, userId)`, then `settleNotStarted(jobId, 'cancelled', 'not picked up', context)`;
   2. emit;
   3. return `The Unity Bridge helper did not pick up the job within 30 s. Nothing ran and the credits were refunded. Ask the user to check the helper is running.`
10. `const final = await handle.waitFinal(BRIDGE_SYNC_WAIT_MS, ctx.abortSignal)`:
    - `'refused'` → return `` `The Unity Bridge helper refused to run this: ${row.error}. Nothing ran and the credits were refunded.` ``;
    - `null` → return `` `Still running on the user's machine as job ${jobId}. Call bridge_job with action "wait" and jobId "${jobId}" to wait for it (up to 90 s per call).` ``.
11. Return `final.image ? { text: header + final.text, image: final.image } : header + final.text`, where

### Algorithms & formulas

- **Service-worker rule 2 (D24)**, replacing `static/__sw__.js:790–797`:
```js
  // 2. only same-origin (and localhost-alias) URLs can belong to a pod;
  //    cross-origin (fonts, CDNs) always passes through.
  //    A localhost-alias URL on a port the pod does not serve is ANOTHER local server
  //    (e.g. a Unity dev server on :8888) and must reach the real network.
  const localAlias =
    url.hostname === "localhost" ||
    url.hostname === "127.0.0.1" ||
    url.hostname === "0.0.0.0";
```

```js
// A localhost-alias URL belongs to the pod only on the app's own port or a port a live
// virtual server registered. When the registry is empty (service worker restarted and
// not yet re-told), keep the old forwarding so previews never break.
function isPodOrSelfPort(url) {
  const defaultPort = (u) => (u.protocol === "https:" ? 443 : 80);
  const port = Number(url.port || defaultPort(url));
  const selfPort = Number(self.location.port || defaultPort(self.location));
  if (url.hostname === self.location.hostname && port === selfPort) return true;
  if (instanceServers.size === 0) return true;
  for (const ports of instanceServers.values()) {
    if (ports.has(port)) return true;
  }
  return false;
}
```

### Error & edge-case policy

| When | Then |
|---|---|
| Tool arg missing or invalid | Return the sentence (never throw), and never debit |
| Device offline at turn start | No tools. Note: `The Unity Bridge is linked to "<device>" but the helper is not running. If the user asks for Unity or Blender work, tell them to run the helper (the cube icon shows the command). Never claim to have run a Unity or Blender command.` |
| No link | No **bridge** tools. `import_local_scene` is still offered (Control flow step 3, D52). Note only if `request.localSceneServer` is present (local-scene note). The identity section covers "not connected" |
