## Codebase Analysis

Grounded in this session's exploration of the licensing/billing modules, the Unity bridge, the projects store, and targeted reads of the reference implementations.

- **Reference implementations (read in full):** `licenser.asmx` (server-side C# generation: `SecurityTools.EncryptString` AES-256-CBC with `PasswordDeriveBytes("12bucklemyshoe", null)` key + IV `xdgrq4yhjmd1ajel`; `ComputeProjectLicenseKeyHash` = MD5 over UTF-16LE of lowercased `<seed>-babylontoolkit.com-05.00.00` with per-part space→underscore, first 28 hex chars uppercased, dash-grouped by 4) and `licenser.cs` (Unity-side validator: decrypts `secret` → `plan|licensee|org|product|project|expires`, recomputes `hash(plan + "-" + PlayerSettings.productGUID)` and compares to `key`; seats `s1`/`s2` are OUTSIDE both the secret and the hash, so they are user-editable post-generation).
- **Live test vector:** `license.json` at repo root — `plan: EnterprisePartner`, `licensee: "Mackey Kinard"`, `secret: "Q1BnvaTaoQ3Bx4ym/C5e3tB10OVxgOmloIrUh8wt7sXom6aq6A46JF3eV9VSBodT"`, `key: "CFA7-9108-9069-F09C-ED6F-1A68-8AB7"`. The secret should decrypt to `EnterprisePartner|Mackey Kinard|*|*|*|never` (per `GeneratePartnerLicense`'s content format) and the key equals `hash("EnterprisePartner-Mackey Kinard")`. Because the IV/key are fixed, encryption is deterministic — re-encrypting the decrypted payload must reproduce the exact base64. One vector pins all three primitives. ⚠️ T1 must first DECRYPT and observe the actual payload, then pin what was observed (never assert an assumed payload blind).
- **.NET `PasswordDeriveBytes` (null salt, default 100 iterations, `GetBytes(32)`)** is PBKDF1-SHA1 with Microsoft's block extension (base = 99 SHA-1 rounds of the password; output = `SHA1(base)` then `SHA1(ASCII(counter) + base)` blocks). Node has no built-in; implement it as a small pure function validated solely by the vector.
- **Plan lookup:** `SUBSCRIPTION_PLANS` (`sub_starter`/`sub_pro`/`sub_studio`) and `findActiveSubscription(userId, context)` in `app/lib/.server/billing/stripe.ts` (Stripe metadata search on server-asserted userId; eventually-consistent; returns null when no sub / not configured). Degrade-to-Indie on any failure.
- **ASMX client to retire:** `app/lib/.server/licensing/licenser.ts` (`validateSubscription` SOAP) + the refresh path in `entitlements.ts` (`refreshEntitlement`, `getEntitlement`, `linkSubscriberEmail`). `resolveByok` stays (inert, `PRO_FEATURES_ENABLED=false`). Callers must be enumerated at execution time (grep `validateSubscription|getEntitlement|linkSubscriberEmail|refreshEntitlement`).
- **Project record:** `Project` in `app/lib/.server/projects/types.ts` (precedent: `gameBackendRef` plain-pointer field); both backends in `store.ts` have `update(id, patch)` (FS ~L140, Supabase ~L289 — the Supabase one needs the field in BOTH `rowToProject` and the `projectToRow` map). Migrations live in `supabase/migrations/`, highest is `0010` → new file is `0011`. The PGlite harness (`ledger-sql.spec.ts`) runs real migrations.
- **Auth walls:** `requireVerifiedUser` (`app/lib/.server/supabase/auth.ts`) + `requireOwnedProject` (`app/lib/.server/projects/ownership.ts`, 404-not-403). Route naming pattern: `app/routes/api.projects.$projectId.<area>.ts`. The `outbound-enumerate.spec.ts` scanner requires every `api.*` handler to reference a wall — the new route will, by construction.
- **Unity bridge client:** `app/components/chat/UnityConnection.tsx` (read in full — icon + `Dialog` in the chat prompt toolbar; connect/disconnect via `connectUnity`/`disconnectUnity`; `unityConnectionAtom`/`unityToolsAtom` from `app/lib/stores/unityBridge.ts`). `callUnityTool(toolName, args)` is callable directly from UI code — no generation, no credits. Unity tool names are discovered dynamically (`unityToolsAtom` entries carry `name`/`description`/`inputSchema`); nothing is hardcoded, so the drop needs a discovery heuristic + graceful fallback. CoplayDev unity-mcp tools can create/modify assets in the open Unity project (companion README); the "no file channel" rule scopes to platform↔project transfers and is not violated by an MCP asset write.
- **Web-file write pattern:** `workbenchStore.createFile(`${WORK_DIR}/<path>`, content)` — the delivery pattern used by `app/lib/media/tasks.ts` (`deliverBytes`).
- **Context budget:** `app/lib/context/opaque-files.ts` — `OPAQUE_FILES` is an exact-path set (project-relative), tested in `opaque-files.spec.ts`. Adding `license.json` makes it a declared-never-shown marker.
- **Owner answers folded in (from the spec's Open Questions):** the live `license.json` is the test vector; a **Download license.json** button IS wanted; `org` is always `"*"` (matches any organization — drop the optional org input); Pro/BYOK re-enablement is manual/testing-only forever — the business is credits-based.

**SPEC.md alignment:** conforms to §4.6 (reads plan state only; never touches the ledger or webhooks), §4.5.3 (two walls, 404-not-403), §4.5.4b (only metadata on the platform; the license file lives in the user's project), §4.2.8 (opaque classification; no prompt-prefix churn — the dialog state is client-only), §4.17 (reserved `unity` server name untouched; direct `callUnityTool`; loopback-only), §5 (crypto server-only). **spec_impact: yes** (from the feature spec): §4.6.1's "license service is the sole authority" and its scope-boundary line are superseded; a new §4.18 records the Unity Project Licenser — written back in the final task.

## Tasks

- [x] **T1** — .NET-compatible crypto core, pinned by the live license vector
  - Files: `app/lib/.server/licensing/unity-license-crypto.ts`, `app/lib/.server/licensing/unity-license-crypto.spec.ts`
  - Details: Implement (a) `dotnetPasswordDeriveBytes(password, count)` — PBKDF1-SHA1 with the MS block extension, null salt, 100 iterations; (b) `encryptLicenseSecret(payload)` / `decryptLicenseSecret(b64)` — AES-256-CBC via `crypto.createCipheriv`, key = derive(`12bucklemyshoe`, 32), IV = UTF-8 bytes of `xdgrq4yhjmd1ajel`, PKCS7; (c) `computeProjectLicenseKeyHash(seed)` — per-part space→underscore, `-babylontoolkit.com-05.00.00` suffix, lowercase, UTF-16LE bytes, MD5, first 28 uppercase hex chars dash-grouped by 4. Constants live in this server-only module. First DECRYPT the repo-root `license.json` secret and observe the payload, then pin the observed value.
  - Acceptance: spec test decrypts the live vector's `secret` to the observed pipe-delimited payload (expected `EnterprisePartner|Mackey Kinard|*|*|*|never`); re-encrypting that payload reproduces the exact base64; `computeProjectLicenseKeyHash('EnterprisePartner-Mackey Kinard')` returns `CFA7-9108-9069-F09C-ED6F-1A68-8AB7`; a round-trip with non-ASCII input survives. If the vector does NOT validate, STOP and report — do not ship unpinned crypto.

- [x] **T2** — Tier mapping + license builder (pure)
  - Files: `app/lib/.server/licensing/unity-license.ts`, `app/lib/.server/licensing/unity-license.spec.ts`
  - Details: `licenseTierForPlan(planId: string | null)` → `{ plan: 'Indie' | 'SmallBusiness' | 'PremiumContent', s1, s2 }`: null/`sub_starter`/unknown → Indie with `s1=s2='locked'`; `sub_pro` → SmallBusiness with `s1=s2=''`; `sub_studio` → PremiumContent with `s1=s2='unlimited'`. `isValidUnityProjectId(id)` — exactly 32 hex chars (normalize to lowercase). `buildUnityLicense({ planId, licensee, unityProjectId, projectName })` → full license object: `org='*'`, `trial=false`, `expires='never'`, `product=unityProjectId`, `project=projectName`, `secret=encrypt('plan|licensee|*|guid|name|never')`, `key=hash(plan+'-'+unityProjectId)`. Never throws on unknown plan ids.
  - Acceptance: exhaustive mapping tests (incl. unknown plan → Indie); field-contract tests; GUID validation rejects empty/31/33/non-hex; the built license's `key` differs for two different Unity project ids (the project lock).

- [x] **T3** — `linkedUnityProjectId` on the Project record + migration 0011
  - Files: `app/lib/.server/projects/types.ts`, `app/lib/.server/projects/store.ts`, `supabase/migrations/0011_unity_project_link.sql`, `app/lib/.server/billing/ledger-sql.spec.ts` (or the harness's schema-pin spec)
  - Details: Add optional `linkedUnityProjectId?: string` to `Project` (doc comment: plain pointer, follows `gameBackendRef`; never a credential). Wire BOTH backends — FS round-trip, and Supabase `rowToProject` (`linked_unity_project_id`) AND the `projectToRow` map (missing either is a silent drop). Migration: `alter table public.projects add column linked_unity_project_id text;` — no constraint tuple needed (a single nullable pointer, unlike the repo link).
  - Acceptance: both store backends round-trip the field (existing store spec pattern extended); the PGlite harness runs 0011 clean and a schema assertion pins the column's existence.

- [x] **T4** — Two-wall route: link / unlink / generate / status
  - Files: `app/routes/api.projects.$projectId.unity-license.ts`, `app/lib/.server/licensing/unity-license-route.spec.ts`
  - Details: Loader (GET): `requireVerifiedUser` + `requireOwnedProject`, returns `{ linkedUnityProjectId, nextTier, notice? }` where `nextTier` comes from `findActiveSubscription(userId)` mapped via `licenseTierForPlan` — any Stripe error/absence degrades to Indie with a `notice`, never throws, never fabricates a paid tier. Action (POST) with body `{ action }`: `link` (validate `isValidUnityProjectId`, `store.update`), `unlink` (clear the field), `generate` (requires a linked id → resolve tier live → `buildUnityLicense` with `licensee = user.email`, `projectName = project.name` → return `{ license, tier }`). No credit debit anywhere; generation is free and idempotent. Route tests live BESIDE the licensing module (never under `app/routes/` — a spec file there 500s every request): stub auth/store/Stripe seams; follow the existing route-spec patterns.
  - Acceptance: unauthenticated → 401; someone else's projectId → 404 (never 403); bad GUID → 4xx with descriptive error; link/unlink round-trip; `generate` returns a license whose fields obey the T2 contract with server-derived `licensee`/`product` (client-supplied email/guid in the body is ignored); Stripe-unreachable path returns Indie + notice; the handler references the walls so `outbound-enumerate.spec.ts` stays green.

- [x] **T7** — Client delivery module: web write, Unity drop, download
  - Files: `app/lib/unity/license-delivery.ts`, `app/lib/unity/license-delivery.spec.ts`
  - Details: Client-safe module with three operations. (a) `writeLicenseToWebProject(license)` → `workbenchStore.createFile(`${WORK_DIR}/license.json`, JSON.stringify(license, null, 2))` (the `media/tasks.ts` pattern); surface the boolean result. No LLM generation, no credits, `unity` reserved-name routing untouched (calls go through `callUnityTool`).
  - Acceptance: unit tests with stubbed `workbenchStore`/`unityBridge` atoms: web write called with the exact root path + pretty JSON; drop is NOT attempted when disconnected (returns `{ ok: false }` without calling `callUnityTool` — mutation-verified); tool-call failure propagates as `{ ok: false, reason }`; a discovered tool receives the `Assets/[Config]/license.json` destination.

## How to execute this plan

Each task above is a checkbox. To implement:
- Run a single task with the bt-execute command (e.g. `bt-execute <this-file> T<n>`), run every remaining task in order with `bt-execute <this-file> ALL` (resumable — it skips tasks already checked), or implement the whole plan from a prompt like "implement the plan at <this-file>".
- Work the tasks top to bottom unless a task notes a different dependency order.
- When a task is fully implemented and its **Acceptance** criteria are met, mark it complete by editing this file and changing that task's `- [ ]` to `- [x]`.
- Stop and report if a task cannot be completed. Do NOT check a box for partial, skipped, or unverified work.
